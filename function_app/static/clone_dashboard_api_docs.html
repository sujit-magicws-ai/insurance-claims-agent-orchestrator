Clone Dashboard — API Integration Reference

How the AI Contractor Workforce Visualizer interacts with the Durable Functions backend

1 Architecture Overview

The Clone Dashboard (/api/clone-dashboard) is a single-page HTML file served by an Azure Function. It has no framework dependencies — just vanilla JS with a polling loop that hits the backend every 500 ms and incrementally updates the DOM.

Each agent lane (Classifier, Adjudicator, Email Composer) displays contractor cards with live progress bars. The compact lanes (Receiver, HITL, Sender) show aggregate counts only.

3b. Claim Status Drill-Down click

GET /api/claims/status/claim-{claim_id}
Opened in a new tab when a user clicks a claim ID in any contractor card's progress bar. Returns the Durable Functions orchestration status including custom_status (current step, progress), timestamps, and final output.

3c. Claims List Dashboard link

GET /api/dashboard
The HITL lane has a "Claims List" link that opens the full claims management dashboard in a new tab. That dashboard shows all orchestrations and provides the manual-estimate review UI.

4 How Data Maps to the UI

UI Element JSON Path Notes
Header — In Flight pill global.total_claims_in_flight Sum of all active jobs across all 3 agent pools
Header — Completed pill global.total_claims_completed Sum of completed jobs across all pools
Header — Pending pill stages.*.pending_count Calculated client-side: sum of pending_count across classifier, adjudicator, email_composer
Receiver lane — count email_receiver.received_count Emails currently being ingested
Agent lane — Workers label stages.{id}.contractor_count / max_contractors e.g. "2/5"
Agent lane — Contractor cards stages.{id}.active_contractors[] Incrementally reconciled — new cards animate in, removed cards fade out
Card — progress bar per job active_contractors[].active_jobs[].progress_pct 0-100; bar turns green at 100%
Card — status badge active_contractors[].status "full" (red), "available" (green), "idle" (gray)
HITL lane — waiting count hitl.waiting_count Claims paused waiting for manual estimate via wait_for_external_event
HITL lane — reviewed count hitl.reviewed_count Claims that have passed through HITL
Sender lane — counts email_sender.sending_count / sent_count Emails in-progress vs completed
Event Log events[] Server-side event array; only re-renders when array length changes

5 Polling Mechanics

  • Interval: 500 ms via setInterval(poll, 500)
  • Connection indicator: Green dot + "live" on success; red dot + "disconnected" on fetch error
  • Incremental DOM updates: Contractor cards are reconciled by ID (card-{stage}-{name}). Existing cards update innerHTML without re-triggering enter animations. New cards get a 2-second green glow (.spawning); removed cards fade out over 500ms (.terminating).
  • Event log optimization: Events only re-render when events.length !== renderedEventCount. Auto-scroll is paused when the user scrolls up manually.

6 Durable Functions Integration Points

The dashboard itself is read-only — it never writes to the orchestration. All mutations happen through other endpoints that feed into the same ContractorManager state:

Durable Functions Concept Backend Endpoint Dashboard Visibility
Start orchestration POST /api/claims/start Card appears in Classifier lane; Receiver count increments
wait_for_external_event("ManualEstimate") Orchestrator pauses HITL waiting count goes up
raise_event (submit estimate) POST /api/claims/approve/{id} HITL count drops; card appears in Adjudicator lane
Activity progress updates ContractorManager (in-memory) Progress bars animate in real time
Orchestration completes Final activity finishes Card removed from Email Composer; Sender sent_count increments
custom_status (step tracking) GET /api/claims/status/{id} Visible when clicking a claim ID link (opens in new tab)
